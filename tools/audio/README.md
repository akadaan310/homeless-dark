# Original audio source experiments

Generate or verify four actual mono 48 kHz, signed little-endian PCM16 WAV files
with Python 3.10+ and its standard library:

```bash
python3 tools/audio/synthesize.py
python3 tools/audio/synthesize.py --check
python3 -m unittest discover -s tests/audio -v
```

Outputs are in `unity/Assets/HOMELESS/Audio/`. Generation atomically replaces each
WAV and writes `evidence/audio/report.json`; `--check` compares regenerated bytes
with the delivered files without replacing them. The four audio files together
remain below 10 MiB. Rights are recorded beside them in
`ORIGINAL_AUDIO_LICENSE.txt` under the project's CC0 original-content convention.

| File | Frames | Duration | Recipe and intended experiment |
| --- | ---: | ---: | --- |
| `synthetic_rain_wind_loop.wav` | 384,000 | 8.00 s | Independent xorshift32 noise, integer low-pass filters and a slow periodic gust multiplier; quiet synthetic outdoor bed |
| `synthetic_footstep_left.wav` | 11,520 | 0.24 s | Seeded filtered noise plus a falling 240–80 Hz sinusoidal impact, short attack and cubic decay |
| `synthetic_footstep_right.wav` | 12,960 | 0.27 s | Different seed and duration for the corresponding impact variant |
| `original_arrival_motif.wav` | 153,600 | 3.20 s | Original authored MIDI pitches 57, 64, 60, 69; sine plus second harmonic, smooth envelopes and two short fixed delays |

These are synthesized sounds, not field recordings, material measurements,
natural speech or imitations of performers. Signal generation uses integer
arithmetic, a literal 32-point sine table with interpolation, explicit sample
counts and fixed PRNG seeds. WAV metadata contains no wall-clock timestamp.
The seeds and exact generator hash are recorded in the report.

The rain/wind file has 30 ms smooth boundary fades. Its last-to-first sample jump
and boundary-slope mismatch are measured, but its deliberate quiet dip is not a
claim of perceptually transparent looping. Footstep variants and motif are one
shots. Individual peaks have headroom; a mixer still needs an explicit voice
count, gain and limiter budget because simultaneous sources can sum.

The report measures decoded PCM peak, RMS, DC mean, clipping, nonzero samples,
frame count, adjacent-sample jumps, boundary jumps, file size and SHA-256. RMS is
not LUFS, and these metrics cannot certify atmosphere, realism, intelligibility
or cinematic quality. Human audition, Unity import, Android decoding, spatial
placement, distance/occlusion, masking and native playback are **NOT_RUN**.

## Bounded world/music fixture

`score(event)` maps an already committed arrival presentation event to ordered
`(MIDI pitch, onset sample frame, duration frames)` tuples. It grants no rights
and commits no world changes. The `street` and `harbor` settings are authored
musical variants; neither claims to represent regional musical traditions.

For this exact integer observable, shifting the event time by 24,000 frames
before mapping gives the same score as shifting every note by 24,000 frames
after mapping. A separate counterexample changes the event's region to
`harbor`, which transposes the motif down five semitones: leaving the old music
unchanged does not commute with that world change. Tests preserve both results.
This small construction is not a universal correspondence theorem or a complete
MATHEMATIC integration. The shipped WAV renders the `street` score at frame zero.

Unity bindings may consume these files as presentation experiments. Event timing,
permission, spatial location and world state remain owned by the runtime; the
audio generator is offline source preparation only (HD-051–055, HD-092).
