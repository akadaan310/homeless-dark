# Native build route

The source project is `unity/`, pinned to Unity **6000.1.0f1 (9ea152932a88)** and URP **17.1.0**, as verified in the nominated Megacity source. This does not adopt that sample's services or content. All direct packages are pinned; a resolved `packages-lock.json` must be produced and reviewed by a real Editor import. It has not been fabricated here.

Current execution host is Linux ARM64, which is not a supported Unity Linux Editor architecture. No accessible x64/macOS Editor worker, Unity license or Galaxy A16 connection was found. No Unity import, C# adapter compilation, scene capture, APK or device benchmark has run. The standalone C# tests do not change those facts.

On an already available compatible worker with eligible, activated Unity and Android Build Support, SDK, NDK and OpenJDK:

```sh
python3 tools/art/fetch_materials.py --help
# Resolve pinned packages and run the Editor tests (adjust Unity executable path).
Unity -batchmode -projectPath "$PWD/unity" -runTests -testPlatform EditMode -testResults "$PWD/artifacts/unity-editmode.xml" -logFile "$PWD/artifacts/unity-tests.log"
# Build an explicitly labeled, controllable source-art inspection scene.
Unity -batchmode -quit -projectPath "$PWD/unity" -executeMethod Homeless.Editor.SourceSceneBuilder.BuildAndroidArtReview -logFile "$PWD/artifacts/android-art-review.log"
```

Create the `artifacts` directory before those commands. The exact art-fetch CLI is documented in `tools/art/UNITY_IMPORT_SPEC.md`; committed, hash-verified CC0 maps and original OBJ make a fetch unnecessary for a normal clone. No account credentials belong in this project.

`HOMELESS > Prepare source art review` imports the original café OBJ, binds URP materials, packs roughness/AO into linear masks, builds static mesh collision, daylight and a local street surface. Original 2K texture files stay intact; Android import uses a provisional 1K ASTC profile, which needs actual device inspection. Wood/cloth/metal look development and the procedural sky are unverified. Geometry is authored fiction, not a reconstruction of the real Tampa café.

The inspection controller supports WASD/right-drag and left/right touch movement/look, pause and focus-loss handling. `R` or **Reset view** returns the inspection visitor to its initial position; falling beyond the finite review surface pauses inspection and displays that recovery option. Original synthesized footsteps, an outdoor rain/wind loop and a short motif are bound to spatial emitters; their native playback and quality remain untested, with a mute control available. These are source-audio experiments, not recorded urban ambience or speech. It is a first-person art-review tool, not the commissioned third-person character experience. It has no qualified humans, traffic, world streaming or saved player journey. `BuildAndroid` deliberately refuses to label it gameplay. The scene is generated by the Editor method; the initial source checkout contains no pretended native scene capture.

Before acceptance, acquire/import realistic rigged people and licensed motion, implement the full arrival and world mechanics, source regional geometry, add spatial audio and vehicles, verify collision/scale under movement, and run the §§87–99 scenarios. Record the actual model/OS/GPU, build hash, quality settings, 20-minute frame-time/thermal trace and continuous gameplay. No FPS or visual-score claim exists yet.
